# components/ui — third-party code

Generated by the shadcn CLI (style `base-nova`, Base UI). **Do not edit these files.**

- Customizations (design tokens, variants, default props, i18n) live in the design system: `components/actions`, `forms`, `feedback`, `overlays`, `display`, `common`.
- Only `components/*` may import from here; the app and features import the design system (ESLint `no-restricted-imports`).
- Update or restore a component at any time:

  ```bash
  pnpm dlx shadcn@latest add <component> --overwrite
  ```

- Add a new one, then create its design-system entry point (`components/<category>/<component>.tsx`).

## Exception on the Next.js 14 line (React 18)

The shadcn CLI only generates React 19 components, where `ref` is a regular prop. On React 18 a ref can't cross a function component, so these files carry **one compatibility patch: `React.forwardRef`**, and nothing else:

| File | Components |
| --- | --- |
| `button.tsx` | `Button` |
| `input.tsx` | `Input` |
| `textarea.tsx` | `Textarea` |
| `input-group.tsx` | `InputGroupButton`, `InputGroupInput` |
| `input-otp.tsx` | `InputOTP` |

After `shadcn add <component> --overwrite` on one of them, re-apply the `forwardRef` wrapper (`git diff` shows exactly what to restore). Any other component that will receive a ref (Base UI `render`, react-hook-form) needs the same patch.
